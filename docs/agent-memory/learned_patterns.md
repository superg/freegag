# Learned patterns

- When an algorithm operates on `std::filesystem::path::string()` storage, convert path character constants such as `preferred_separator` to the string's character type explicitly. On Windows, the path's native character type is `wchar_t` even though `path.string()` returns `std::string`, so unconstrained template deduction can reject mixed `char` and `wchar_t` replacement values.
- Treat script-serialized host filenames as case-insensitive content paths. On case-sensitive filesystems, resolve each path component to the existing case-insensitive match before host existence/open checks; otherwise a Windows-authored save such as `source=gag01.cdf` cannot reopen host file `Gag01.cdf`, and retaining the previous archive can turn the path failure into misleading missing-resource errors.
- Use SDL main callbacks for an event-driven game host that must continue during native window move/resize loops. With the callback rate set to `waitevent`, normal idle operation remains blocking, while SDL invokes the same queued host-event iteration from supported platform live-resize hooks. Keep presentation notifications coalesced, upload only new snapshots, and repaint size/expose changes from the cached texture so modal interaction cannot create an unbounded event backlog or repeated full-frame uploads.
- Preserve the original window pause policy independently of input focus: pause the coordinated runtime only for `SDL_EVENT_WINDOW_MINIMIZED`, resume it for `SDL_EVENT_WINDOW_RESTORED`, and let a visible window continue running whether focused or not.
- `NOCOMMENT` is the persisted subtitle-suppression link for both generic-text paths: animation `/TEXT` associations built with resources and script `TEXT` opcodes used by interaction events. Because a new-game session reset clears runtime-root flags, restore the application preference before constructing the next script tree and again afterward. Suppress only generic text attachment so animation, speech audio, event flow, and hover-comment mechanics remain intact.
- Before the XRGB split, a logical scene index identified one shared indexed canvas, not one surface per resource owner. Multiple resources acquired descriptors into that canvas at their offsets, so animation replacement, moved overlays, palette state, and `NOCLS` persistence were scene-level behavior. A portable XRGB renderer should preserve that invariant with an authoritative composition plus shared indexed backing/history; per-resource layers and geometry-based handoff rules are not equivalent.
- Create the SDL application window hidden when persisted geometry or initial fullscreen state must be applied after video/display initialization. Apply and validate the final state first, then show explicitly so the platform compositor never presents the temporary logical-size window.
- XTET host-event and input-drain callback registration is process-lifetime host configuration, not per-game instance state. `initialize_game` may reset an old instance through `shutdown_game`, so instance teardown must not silently unregister callbacks that the loader supplied for the new instance.
- SDL text input carries printable text but not translated control characters such as Enter and Backspace. Feed printable bytes only from `SDL_EVENT_TEXT_INPUT`, and translate key-down for the legacy byte-input controls (including keypad Enter) so text is not duplicated and `INPSTR` can terminate or edit as before.
- The engine's empty installation prefix means the process working directory. Preserve bare relative filenames for actual save/archive I/O, but normalize an empty directory operand to `"."` before constructing a `std::filesystem::directory_iterator`; an empty filesystem path is not a portable synonym for the current directory.
- Preserve cursor position across asynchronous fullscreen transitions in logical game coordinates. Capture through the old renderer viewport, wait for SDL's matching fullscreen-state event, convert through the new letterboxed viewport, and then warp; raw window or desktop coordinates do not preserve the pointed-at game location.
- Treat window enter and leave as cursor-state recovery boundaries. Leaving must expose the system cursor and notify gameplay; entering must re-query and hit-test the current logical position, then republish pointer movement and select the software or system cursor accordingly instead of relying on a prior motion/leave sequence.
- Animation terminal callbacks run on their backend's worker and must not synchronously destroy or join that backend. Enqueue terminal resource destruction for the script/runtime owner, let the worker return, then join and free it on the owner thread; publish resource-count completion only after destruction finishes, and drain the queue inside any wait that depends on that count.
- Portable game paths use an empty installation prefix and retain bare relative archive/file names, including `XTETDLL.SFS`; resolve them from the process working directory rather than the executable directory or drive scans.
- Local archive startup must not benchmark throughput or reject/prompt based on the original CD-drive speed threshold.
- Local preferences belong in `freegag.ini` in the process working directory. Read and write them with standard streams, preserve strict numeric validation and fallback behavior, and emit LF line endings on every platform.
- Preference reads and writes are nonfatal. Parse named game booleans independently with explicit defaults, and accept window geometry only when all four coordinates parse, meet minimum dimensions, avoid arithmetic overflow, and intersect a monitor.
- When a preference file is intentionally canonical rather than extensible, deserialize only recognized values into a typed snapshot and regenerate only the supported schema. Do not feed the raw parsed key map back to the writer, because doing so silently preserves legacy and unknown entries.
- Keep positive user-facing booleans positive across parsing, internal state, menu toggles, and serialization. When an engine flag such as `NOCOMMENT` has inverse semantics, perform that inversion only at the engine boundary rather than in the preference value.
- Expose audio availability as positive `Sound`, defaulting true, and translate false to the engine's internal mute flag. Do not leak inverse implementation flags into the canonical preference schema.
- Use one renderer logical-presentation choice for windowed and fullscreen scaling when both modes are meant to match. Map `IntegerScaling=true` to whole-number scaling and false to aspect-preserving letterboxing before creating the renderer; texture filtering remains nearest-neighbor independently.
- Separate legacy resource-depth selection from modern host framebuffer depth. Low-color mode can select script variant 0 while retaining indexed source decoding and the XRGB8888 compositor; it does not require an 8-bit SDL window or presentation texture.
- Audit legacy color variants from script `:0`/`:1` selectors rather than filename extensions alone. Most variant-0 assets use `.256`, but low-color assets can retain `.BMP` or `.MOV` extensions; both low- and high-color bitmap alternatives may themselves be stored as indexed 8-bit BMP data.
- Distinguish indexed source depth from the frame's aggregate color capacity. An indexed asset can carry its own 256-entry palette and expand losslessly (apart from RGB565 precision) into a high-color destination; composing several such assets can therefore display far more than 256 colors. An 8-bit destination has one active palette for the whole frame and must remap other resource palettes to it, which is why separately authored low-color variants can be necessary even when every source file is indexed.
- Treat CDF media type as payload-based rather than extension-based. Bitmap data normally uses `.BMP` or `.256`, but resources such as `FONT2.RUS` can also contain a complete BMP payload.
- Interpret an indexed BMP palette as `RGBQUAD` storage: B, G, R, and a reserved byte. The color is 24-bit even though the record occupies four bytes; do not infer alpha semantics from a nonzero reserved byte when the game decoder explicitly ignores it.
- Keep the fixed-capacity application message table layout unchanged even when legacy diagnostics become unreachable.
- During the current high-change cleanup phase, keep the repository free of first-party tests and explicit test hooks. Do not add or restore tests without an explicit user instruction; future reenablement remains intentionally unspecified.
- Game-state save and load always use the scripted in-game `SAVELOAD.CFG` flow. Do not reintroduce a build option or the recovered native dialog path; keep shared archive enumeration and CDF persistence available to the scripted UI and autosave.
- The portable SDL desktop path is the sole production behavior. Do not reintroduce `FREEGAG_WINDOWS_FIXES`, native window branches, or physical display-mode switching.
- Treat decompilation as complete: do not add executable-address annotations, recovered layout assertions, provenance labels, address-derived identifiers, or intentional emulation of undefined stack values. Comments should explain current behavior and maintenance constraints.
- Keep production source free of `_DEBUG` blocks and debug-only trace infrastructure unless the user explicitly requests diagnostic instrumentation later.
- Set the C++ language level globally in the root CMake file (`CMAKE_CXX_STANDARD 23`, required, extensions off) instead of repeating target-level compile features.
- Discover formatter inputs with one root-level recursive glob over `src/*.cpp`, `src/*.h`, `tools/*.cpp`, and `tools/*.h`; do not maintain propagated per-directory source lists or include in-tree build dependencies.
- XTET is statically integrated; keep its application boundary in `src/xtet/integration.cpp` and do not reintroduce unused DLL entry-point typedefs or DLL-lifecycle framing.
- Keep XTET's public host boundary platform-neutral. Feed it typed runtime mouse, button, key, and text events, and keep SDL event translation in the application host.
- Use `std::chrono::steady_clock` for XTET's monotonic millisecond timestamps and `std::this_thread::sleep_for` for animation delays; XTET does not require `winmm`.
- Report XTET initialization failures with exceptions. Keep cleanup at the existing startup exception boundary rather than adding XTET-owned debugger output or dialogs.
- Use the standard `main(int, char **)` entry point and CMake's console executable default. Consume supported switches directly from `argv`; startup does not require a native process-instance handle.
- Keep project-added save/load and synthesized-resource implementation under `src/extra/`, list those files directly in `src/CMakeLists.txt`, and do not add `src/extra/CMakeLists.txt`.
- Keep the stock game runtime split by functional ownership under `src/`: application/window state, display host, display scene, runtime control, script language, runtime trees, runtime model, resources, media, text, audio, and XTET game hosting. Reserve `startup.*` for the executable entry facade and startup/message-loop orchestration.
- Preserve legacy cross-module layouts in the ordered `*_types.h` layer during mechanical reorganization. Keep `runtime_internal.h` private to runtime implementation files; `main.cpp`, archive code, and `src/extra` must consume specific functional headers instead.
- Treat scripts and runtime trees as the orchestration layer: application code hosts the process and windows, while tree links and script opcodes drive logical objects, resource construction, scene changes, interaction, media, audio, save/load, and XTET dispatch.
- Preserve the current threading boundaries during further cleanup: SDL UI/event handling, script execution, scene presentation, SDL-demanded sound mixing (or its silent fallback worker), asynchronous file I/O, and animation decoding remain separate execution contexts and synchronize through portable queues, recursive mutexes, and manual-reset events.
- Fetch SDL 3.4.10 as a pinned static dependency while keeping the root project `LANGUAGES CXX`; disable SDL's shared target, tests, test library, examples, documentation, and installation, and link SDL only to the game executable.
- Keep SDL's optional file-dialog subsystem disabled. Project errors report to `stderr`; the Windows video backend's independently compiled simple-message-box implementation may remain in the static SDL binary even when the game never invokes it.
- Give each logical sound handle its own SDL audio stream, with the stream input specification copied from the asset's `RuntimePcmFormat`. Keep source bytes unconverted across queued segment boundaries and let bound SDL streams perform conversion, resampling, float mixing, and final device conversion; do not reintroduce a project mixer or intermediate integer buffers.
- Preserve the two distinct legacy audio markers in per-stream transport: playback completion follows buffer consumption, while animation schedule readiness is raised only after a legacy-sized source PCM block has been consumed and the next block pass begins. SDL's first demand callback is not itself schedule readiness. The old shared mixer also imposed global block-phase latency on newly queued voices; independent SDL streams do not naturally reproduce that incidental, phase-dependent delay.
- Keep sound queues, SDL streams, loop state, and fade state private to `audio.cpp`. Expose synchronized status snapshots and narrow marker/restart operations instead of pointers to mutable slot layouts.
- Serialize sound replacement and control transitions by disabling the stream callback, unbinding the voice, waiting for any callback to leave, mutating queue state, and then restoring the stream binding. Do not call SDL while holding a per-voice state mutex.
- Treat device and individual-stream failures as nonfatal. A 5-ms control `std::jthread` advances unbound voices from their native sample rates without decoding or mixing, while close-output pause deliberately suspends that progression.
- Revert any unsuccessful attempted fix once the actual solution is found; do not retain unrelated behavioral, lifecycle, or architectural changes whose underlying hypothesis was disproved. SDL device opening remains in sound initialization and reopening remains in explicit output resume handling.
- Preserve the stock engine's content-acceptance boundary during subsystem refactors. Do not add inferred RIFF, animation-frame, chunk-size, frame-alignment, or PCM-metadata consistency validators that can reject assets the original paths accepted. Where required internally, derive PCM block alignment and average byte rate exactly as the legacy mixer did while retaining its existing format restrictions.
- Represent game-side PCM metadata with `RuntimePcmFormat`; adapt XTET's PCM descriptor explicitly at the host boundary rather than relying on identical structure layouts through a function-pointer cast.
- Use `runtime_milliseconds()` as the shared game clock. It is based on `std::chrono::steady_clock` and deliberately truncates elapsed milliseconds to 32 bits so existing unsigned timeout and synchronization arithmetic keeps its wraparound behavior.
- Keep SDL window, renderer, texture, and event operations on the UI thread. Cross-thread display producers update CPU state and post a typed presentation event; the registered SDL user-event doorbell wakes the UI loop without carrying framebuffer data or exposing SDL rendering APIs to workers.
- Preserve the distinction between the compositor root and the visible presentation front buffer. Region-copy operations reveal root pixels, while blackout operations modify only the front buffer; collapsing both into a latest-root upload breaks scene transitions.
- Use a bounded pool of reusable full-frame presentation snapshots to preserve transition order without per-frame allocation. Signal cancellation before joining display producers so a full queue cannot deadlock shutdown.
- Never let the SDL UI thread block on XTET's gameplay mutex while the XTET worker can block on the UI-drained presentation queue. Filter unrelated SDL events before gameplay synchronization and acquire the gameplay lock nonblockingly so presenter wake events can run first.
- Keep game-domain events independent of the platform event representation. Use owned typed C++ payloads and cancellable completions for cross-thread work; the platform callback is only a coalesced, payload-free doorbell that asks the UI thread to drain the queue.
- When an owned string crosses back into a legacy script-name API, rematerialize it as a zero-initialized 32-byte field before lookup. Those APIs compare the entire fixed-width field; `std::string::c_str()` guarantees only one terminator and is not a zero-padded substitute.
- Dispatch synchronous host events directly when already on the UI thread. Cross-thread sends wait on a shared completion, and commands that historically used `ReplyMessage` acknowledge that completion before continuing long UI-thread work. Close the dispatcher only after producers stop, and release every queued waiter during cancellation.
- Let SDL own system-cursor visibility for the sole application window. Game cursors remain software-composited, including intentionally bitmap-less script cursors used during video playback.
- Keep indexed graphics as source/decode state and XRGB8888 as the only writable render/composition format. Expand an indexed source through its own palette at the draw boundary; never quantize it through a destination palette or a lower-precision packed format.
- Preserve legacy index-zero transparency in XRGB surfaces with a keyed-visibility marker in the ignored high byte. SDL presentation treats the surface as XRGB, while transparent scene composition tests the marker instead of RGB values.
- Keep screenshot capture limited to savegame previews. Embedded previews must retain the original indexed BMP format for cross-version save compatibility; do not reintroduce the standalone Win32 screenshot export or route save thumbnails through a full-color serializer.
- Treat every pixel decoded from a savegame preview as opaque, including palette index 0. Reserve marker-zero XRGB pixels for clearing or hiding the preview layer; interpreting the saved bitmap's index 0 as transparent drops legitimate black image areas.
- Treat main-menu hover highlights as static BMP resources activated by script `PLAY` commands, not animation files. Ordinary shared static bitmaps may intentionally bind the same writable XRGB composition scene and expand directly into it.
- Do not use resource load order or media type to assign an ordinary resource its own pixel surface. Static bitmaps and animations, including permanent and control resources, participate in their logical scene's shared XRGB composition and indexed history. Reserve independent indexed sources for script semantics that explicitly allocate a separated, private, or load-only scene.
- Treat a logical scene index as the identity of one authoritative composition canvas. Its XRGB pixels and scene-sized indexed backing are two representations of the same scene state; resources receive descriptor offsets into both. Independent source nodes may coexist only when the script created genuinely distinct scene semantics, and index lookup continues to prefer the composition node.
- Treat script `NOCLS` as “end the resource without clearing its scene region.” Pixel continuity belongs to the logical scene lifetime, not to an ownerless resource surface or a geometry-matched successor. Normal clears must update both XRGB and indexed representations so later delta frames cannot resurrect stale pixels.
- Font atlases use indexed pixels as masks, while script-supplied low/high colors select indices in the active game palette. Resolve the remapped glyph index through the active palette when writing XRGB; the font bitmap's own palette is not the text-color authority.
- Decode an XRGB-bound animation into its logical scene's shared indexed backing using the resource's scene offset and the scene stride. Materialize only the animation's clipped dirty rectangle into XRGB; palette-only frames may rematerialize the animation extent, but must not overwrite unrelated scene pixels.
- Use one ASCII-specific case-insensitive comparator for archive names, script identifiers, extensions, and synthesized resource names; locale-sensitive platform string APIs are not part of these file formats.
- Enumerate scripted saves with `std::filesystem`, match the extension case-insensitively, and sort by filename before reading comments so discovery order is stable across filesystems.
- Keep application commands typed and independent of the platform event loop. Scripted fullscreen selection dispatches `ApplicationAction`; it must not imply an Alt+Enter shortcut.
- Keep CDF archive representation and source selection private to `cdf_archive.cpp`. Use owned standard streams directly for ordinary archive I/O, while duplicated asynchronous records share a narrow mutex-protected random-access file object and maintain independent logical offsets.
- Use `RuntimeHeap` where legacy subsystems require zeroed allocation, reallocation, individual release, and release-all destruction. Do not recreate Win32 heap typedefs or flags in public types.
- Encode and decode BMP integer fields explicitly as little-endian bytes. Fixed-width project structs describe the logical fields, but raw save/archive bytes must not depend on host structure packing or endianness.
- Treat legacy DOS separators and `.DLL` names inside game/archive protocols as content syntax, but normalize both `/` and `\\` whenever a path crosses into host-filesystem handling. A content identifier is not itself a native-library dependency.
- A platform-neutral API audit is not multiplatform verification. Require at least one non-Windows configure/build and a representative runtime smoke test (preferably automated in CI) before describing a host port as verified.
- Keep project implementation members directly in the `freegag` or `xtet` namespace rather than nesting anonymous namespaces inside them. Because these helpers then have named-namespace linkage, give otherwise repeated generic helpers subsystem-specific names, such as `tokenize_asset_manifest` and `tokenize_scene_description`, to avoid cross-translation-unit collisions.
- Omit optional braces from simple single-statement control bodies through the repository's `RemoveBracesLLVM: true` formatter policy. Accept clang-format's conservative retention of braces where removing them would make an `if`/`else` chain asymmetric or potentially ambiguous; do not perform a broader manual brace-removal pass.
- Keep numerically overlapping legacy flags in separate unscoped enum domains that follow their owning state word; equal bit values in application, display, resource, media, async-file, script-tree, and XTET state do not imply shared semantics. Express mutation with named values and `|`/`& ~`, and remove one-line mutator wrappers when direct mutation is clearer at the call site.
- Rename decompiled fields from observed behavior only. When a layout member has no reads or writes that establish a role, name it `reserved_<offset>` instead of preserving `unknown_*`/`field_*` or inventing semantics. Treat parser scope numbers as typed protocol tokens rather than bit flags.
- Name every enum member with uppercase snake case, regardless of whether its enum is scoped or unscoped; retain Pascal case for enum type names.
- Do not classify every hexadecimal return value as a flag. The display-scene API uses exact operation results (`0` success, generic failure, lock-not-owned) and also propagates its release-pending lock bit as a distinct retry result; model exact results as statuses while retaining the pending value's connection to lock state.
- Keep return protocols domain-specific even when they reuse the same numeric sentinel. Parser exhaustion, invalid integers, unavailable sound handles, unbounded frame limits, inactive movement deadlines, missing text positions, special scene indices, archive errors, and display failures are different contracts and need distinct names. Remove a return value entirely when all callers discard it and the function only performs an action.
- Treat empty-brace field declarations as behavioral defaults, not decoration: removing `member{}` changes plain default construction from zero-initialized to indeterminate. Binary overlay structs may omit such defaults when every construction site either fully writes the object or explicitly value-initializes it, but stateful types require a construction-site audit first.
- Remove fixed internal function-pointer forwarding tables when they have one immutable initializer and no ABI, implementation-switching, or testing role. Use direct typed calls rather than preserving manual-vtable indirection and `void *` erasure; retain callback tables only at genuine dynamic boundaries.
- Represent a genuine single callback dependency as a named function-pointer type stored beside its context, not as a one-member `*Api` struct. If a parameterized source has only one project implementation and no independent consumer, call that source directly instead of retaining an artificial callback bundle.
- Do not retain a one-field result struct when its field is never consumed and its address serves only as a success token. Return `bool` and remove any downstream opaque context storage once its consumers are confirmed to ignore it.
- Remove lifecycle flags whose first mandatory initialization permanently establishes the only state later consumers accept. Keep the underlying stage execution intact, but eliminate write-only accumulation, never-cleared lock bits, and readiness checks that are provably true for every live object.
- When every call passes `nullptr` to an optional output/alternate-path parameter and the pointed-to type has no serialization or ABI role, remove the unreachable branch, parameter, and dead type together rather than preserving unused `reserved_*` layout fields.
- Keep raw numeric command storage at a script/event boundary when unknown or subsystem-specific messages must pass through, but convert once to a scoped command enum before application dispatch. Name members by observed behavior and use those names for cases and comparisons so protocol values do not leak through handler logic.
- Treat `0x03000000` and `0x07000000` as encoded script boolean payloads, not application flags: use `SCRIPT_BOOLEAN_TRUE`/`SCRIPT_BOOLEAN_FALSE` and pass `SCRIPT_VALUE_TYPE_BOOLEAN` to field resolution. Do not conflate them with numerically similar eight-digit scope or opcode values such as `0x30000000` and `0x70000000`.
- When a callback operation number selects a stable internal service, type the operation in the callback signature itself and propagate that enum through every caller. Once the callback is fixed and local, align its full signature, assign it directly, remove type-erasing adapters and universally unused arguments, and delete notifications with no handled operation rather than naming a no-op.
- When a formerly dynamic module is statically linked, audit callback tables by consumer reads rather than preserving the recovered slot count. Replace the surviving slots with named typed fields, remove copied-but-unread services, and avoid storing function pointers in `void *`; numeric tables can conceal ordering defects that typed initialization exposes.
- Do not immediately repost a contended gameplay input into SDL when the mutex owner may be blocked on UI-thread presentation. A continuously reposted event keeps the event queue nonempty, can starve the SDL iterate callback that drains the bounded presentation queue, and turns temporary lock contention into deadlock. Consume animation-time input when the game already flushes it at the interaction boundary, or retain it in an application-owned retry mechanism that runs only after presenter service.
- Infer decompiled configuration units from the final arithmetic consumer, not only from script labels. A value serialized as a fade setting may actually be a per-update channel or geometry step, while a host "mode" used as `bytes / value` against a millisecond clock is a byte-per-millisecond rate; represent an option value as a flag mask only when its consumer performs bit selection.
- Inline one-statement helpers used at only one or two ordinary call sites when doing so exposes the operation more clearly, and delete declaration-only/dead accessors. Retain small functions that are required callbacks, entry points, destructors, encapsulation boundaries for private subsystem state, or names for reused legacy formulas and flag semantics; low call count alone does not justify breaking ownership or type boundaries.
- Before naming a recovered stage mask, compare every tested bit with the fixed combinations supplied by callers. If bits are never passed, shadowed by earlier branches, or group unrelated one-time operations, split the dispatcher into focused operations instead of preserving an artificial flag protocol merely by adding an enum.
- A recovered fixed-stride message table is not a protocol merely because consumers use pointer arithmetic. Trace every index and the base pointer's lifetime; when only a few constant strings remain and the layout has no serialization or ABI role, replace live entries with named string constants and remove the stride helper, unused messages, and state-held base pointer together.
- Register project-added content in the synthesized-resource table and select it by filename through the stock resource path. Let a real CDF entry take precedence and synthesize only after an archive miss; avoid mode-dependent virtual-content interception when a startup option only needs to choose an alternate script name.
- Express project-added scene transitions in the synthesized script itself. Use the script language's explicit no-fade load/reload operation when an immediate handoff is required; leaving the transition unspecified permits the runtime to choose randomly from its enabled transition options.
- Preserve XTET mouse controls as edge-triggered unless deliberately adding a usability extension. The original DLL hit-tests controls on `WM_LBUTTONDOWN`, performs one action, and does not implement held-button autorepeat; keyboard repetition is a separate host-generated behavior.
- Do not group equal sentinel bit patterns into one enum solely because their representations match. Loop-count infinity and marker-state sentinels belong to separate semantic domains; also verify the zero/nonzero protocol before naming a recovered sentinel `UNSET`.
- Prefer one invalid value for internal numeric handles when all operations share one validity range and callers do not distinguish failure causes. Multiple rejected sentinels are harmful when consumers use a simpler `handle != 0` success test; normalize failures at creation instead of preserving an unobserved legacy distinction.
- Do not retain a generic virtual stream hierarchy when one subsystem is its sole consumer and callers must downcast to recover concrete capabilities. Keep ordinary file streams directly in the owning subsystem, but preserve a narrow synchronized random-access file object when duplicated asynchronous readers share one physical stream and require independent logical offsets.
- Use a named fixed-width bit constant instead of a one-member enum when the serialized field combines a value from another domain with one independent modifier bit and the enum type itself is never used by an interface or object field.
- Once a recovered host context no longer crosses a serialization or dynamic ABI boundary, do not preserve reserved layout slots or write-only mirrors. Passing its address as an opaque callback context does not make its layout significant when the callback ignores that argument; retain only members with actual readers.
- Distinguish an actively queued two-word record from a layout-only byte wrapper. Give queue records typed event fields and behavior-derived payload names; replace a structure used solely to copy bytes into string consumers with an appropriately sized character container when no ABI or serialization contract exists.
- For whole-repository dead-code passes, combine compiler warnings with declaration/reference counts, explicit member-access and write-only scans, and call-chain inspection. Treat findings as candidates until aggregate initialization, whole-object copies, callbacks, raw file overlays, and intentional cross-type layout views are checked; unread bytes in a serialized overlay or a verified layout alias are not removable dead fields.
- When recovered code reinterprets one structure as another, treat every offset reached through either view as live even if its declaration has no direct member access. Give alignment members names that expose the alternate-view role and lock the contract down with `offsetof` and total-size assertions before removing or reordering fields.
- Do not promise exact top-level window-position persistence on native Wayland: the compositor does not expose or honor those coordinates, and SDL reports a synthetic display-origin position. When exact placement is a product requirement on Linux, prefer X11/XWayland with Wayland as fallback and use default hint priority so an explicit user-selected SDL video backend remains authoritative.
- Do not make initial asynchronous-resource registration depend on the worker reaching its normal frame callback before another script command can pause it. A pause-notification callback must consume the same pending-registration state as the normal callback; otherwise a scheduling change can strand the global resource count below a synchronous wait target forever.
- When repairing asynchronous resource registration, distinguish callers that snapshot their expected count before worker startup from constructors that snapshot it afterward. An early worker-side increment is safe only for the former; for the latter it moves the baseline and makes the constructor wait for a duplicate increment.
- Do not write an entire asynchronous state word back from a callback-time snapshot when construction or finalization can mutate it concurrently. Serialize with the lifecycle operation, reread the live word under that lock, and change only the owned bit; otherwise a registration fix can restore an obsolete initial pause and strand a valid secondary animation at frame zero.
- Do not translate a Win32 `PeekMessage(..., WM_KEYFIRST, WM_KEYLAST, PM_REMOVE)` drain into `SDL_FlushEvents` alone. If a recovered animation sleeps synchronously inside an SDL main-thread event callback, SDL cannot pump native input during the animation; provide the delay through the host so main-thread waits can pump and flush keyboard events while preserving the animation deadline, while worker-thread waits remain ordinary delays. Route worker end drains through a typed host event and retain a generation-based discard boundary through the next presenter-service iteration to cover SDL callback-prefetched events without an elapsed-time acceptance heuristic.
- Preserve a script-supplied animation control word when translating recovered bit arithmetic. In `set_runtime_resource_state`, state `0` means normal play, state `1` means pause, and additional bits request controls such as one-step and restart; reducing nonzero state to a boolean pause silently disables those composite commands. Clear only the state-owned paused/one-step bits, then merge the complete requested word, matching the recovered operation.
- Treat software-cursor selection and movement as one cross-thread state machine. Serializing individual display-resource operations is insufficient: a UI thread can retain the former cursor identity across a script-thread switch and move that parked scene back onscreen. Guard acquisition, movement, replacement, and suspend/resume deferred identity bookkeeping with the same recursive lock so no stale cursor operation can outlive a switch.
