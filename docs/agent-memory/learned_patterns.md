# Learned patterns

- Portable game paths use an empty installation prefix and retain bare relative archive/file names, including `XTETDLL.SFS`; resolve them from the process working directory rather than the executable directory or drive scans.
- Local archive startup must not benchmark throughput or reject/prompt based on the original CD-drive speed threshold.
- Local preferences belong in `freegag.ini` in the process working directory. Resolve its explicit `.\\freegag.ini` name to an absolute path before calling Win32 profile APIs, because bare profile filenames otherwise use Windows-specific search behavior.
- Preference reads and writes are nonfatal. Apply the existing settings mask only after strict numeric parsing, and accept window geometry only when all four coordinates parse, meet minimum dimensions, avoid arithmetic overflow, and intersect a monitor.
- Keep the fixed-capacity application message table layout unchanged even when legacy diagnostics become unreachable.
- During the current high-change cleanup phase, keep the repository free of first-party tests and explicit test hooks. Do not add or restore tests without an explicit user instruction; future reenablement remains intentionally unspecified.
- Game-state save and load always use the scripted in-game `SAVELOAD.CFG` flow. Do not reintroduce a build option or the recovered native dialog path; keep shared archive enumeration and CDF persistence available to the scripted UI and autosave.
- Modern Windows compatibility is the sole production behavior. Do not reintroduce `FREEGAG_WINDOWS_FIXES`, its legacy branches, or physical display-mode switching; fullscreen is implemented as a borderless window.
- Treat decompilation as complete: do not add executable-address annotations, recovered layout assertions, provenance labels, address-derived identifiers, or intentional emulation of undefined stack values. Comments should explain current behavior and maintenance constraints.
- Keep production source free of `_DEBUG` blocks and debug-only trace infrastructure unless the user explicitly requests diagnostic instrumentation later.
- Set the C++ language level globally in the root CMake file (`CMAKE_CXX_STANDARD 23`, required, extensions off) instead of repeating target-level compile features.
- Discover formatter inputs with one root-level recursive glob over `src/*.cpp`, `src/*.h`, `tools/*.cpp`, and `tools/*.h`; do not maintain propagated per-directory source lists or include in-tree build dependencies.
- XTET is statically integrated; keep its application boundary in `src/xtet/integration.cpp` and do not reintroduce unused DLL entry-point typedefs or DLL-lifecycle framing.
- Keep XTET's platform-specific host interaction localized to `src/xtet/integration.cpp`; its public host context currently requires Win32 window, graphics-handle, palette, and message types.
- Use `std::chrono::steady_clock` for XTET's monotonic millisecond timestamps and `std::this_thread::sleep_for` for animation delays; XTET does not require `winmm`.
- Report XTET initialization failures with exceptions. Keep cleanup at the existing startup exception boundary rather than adding XTET-owned debugger output or dialogs.
- Use the standard `main(int, char **)` entry point and CMake's console executable default. Acquire the `HINSTANCE` inside startup with `GetModuleHandleA(nullptr)` and consume supported switches directly from `argv`.
- Keep project-added save/load and synthesized-resource implementation under `src/extra/`, list those files directly in `src/CMakeLists.txt`, and do not add `src/extra/CMakeLists.txt`.
- Keep the stock game runtime split by functional ownership under `src/`: application/window state, display host, display scene, runtime control, script language, runtime trees, runtime model, resources, media, text, audio, and XTET game hosting. Reserve `startup.*` for the executable entry facade and startup/message-loop orchestration.
- Preserve legacy cross-module layouts in the ordered `*_types.h` layer during mechanical reorganization. Keep `runtime_internal.h` private to runtime implementation files; `main.cpp`, archive code, and `src/extra` must consume specific functional headers instead.
- Treat scripts and runtime trees as the orchestration layer: application code hosts the process and windows, while tree links and script opcodes drive logical objects, resource construction, scene changes, interaction, media, audio, save/load, and XTET dispatch.
- Preserve the current threading boundaries during further cleanup: Win32 UI/message handling, script execution, scene presentation, SDL-demanded sound mixing (or its silent fallback worker), asynchronous file I/O, and animation decoding remain separate execution contexts and synchronize through the existing queues, messages, locks, and events.
- Fetch SDL 3.4.10 as a pinned static dependency while keeping the root project `LANGUAGES CXX`; disable SDL's shared target, tests, test library, examples, documentation, and installation, and link SDL only to the game executable.
- Give each logical sound handle its own SDL audio stream, with the stream input specification copied from the asset's `RuntimePcmFormat`. Keep source bytes unconverted across queued segment boundaries and let bound SDL streams perform conversion, resampling, float mixing, and final device conversion; do not reintroduce a project mixer or intermediate integer buffers.
- Preserve the two distinct legacy audio markers in per-stream transport: playback completion follows buffer consumption, while animation schedule readiness is raised only after a legacy-sized source PCM block has been consumed and the next block pass begins. SDL's first demand callback is not itself schedule readiness. The old shared mixer also imposed global block-phase latency on newly queued voices; independent SDL streams do not naturally reproduce that incidental, phase-dependent delay.
- Keep sound queues, SDL streams, loop state, and fade state private to `audio.cpp`. Expose synchronized status snapshots and narrow marker/restart operations instead of pointers to mutable slot layouts.
- Serialize sound replacement and control transitions by disabling the stream callback, unbinding the voice, waiting for any callback to leave, mutating queue state, and then restoring the stream binding. Do not call SDL while holding a per-voice state mutex.
- Treat device and individual-stream failures as nonfatal. A 5-ms control `std::jthread` advances unbound voices from their native sample rates without decoding or mixing, while close-output pause deliberately suspends that progression.
- Revert any unsuccessful attempted fix once the actual solution is found; do not retain unrelated behavioral, lifecycle, or architectural changes whose underlying hypothesis was disproved. SDL device opening remains in sound initialization and reopening remains in explicit output resume handling.
- Preserve the stock engine's content-acceptance boundary during subsystem refactors. Do not add inferred RIFF, animation-frame, chunk-size, frame-alignment, or PCM-metadata consistency validators that can reject assets the original paths accepted. Where required internally, derive PCM block alignment and average byte rate exactly as the legacy mixer did while retaining its existing format restrictions.
- Represent game-side PCM metadata with `RuntimePcmFormat`; adapt XTET's PCM descriptor explicitly at the host boundary rather than relying on identical structure layouts through a function-pointer cast.
- Use `runtime_milliseconds()` as the shared game clock. It is based on `std::chrono::steady_clock` and deliberately truncates elapsed milliseconds to 32 bits so existing unsigned timeout and synchronization arithmetic keeps its wraparound behavior.
- Keep SDL renderer, texture, and wrapped-window operations on the UI thread. Cross-thread display producers update CPU state and post a typed presentation event; the platform-specific doorbell wakes the UI loop without carrying framebuffer data or exposing SDL rendering APIs to workers.
- Preserve the distinction between the compositor root and the visible presentation front buffer. Region-copy operations reveal root pixels, while blackout operations modify only the front buffer; collapsing both into a latest-root upload breaks scene transitions.
- Use a bounded pool of reusable full-frame presentation snapshots to preserve transition order without per-frame allocation. Signal cancellation before joining display producers so a full queue cannot deadlock shutdown.
- Never let the Win32 UI thread block on XTET's gameplay mutex while the XTET worker can block on the UI-drained presentation queue. Filter unrelated window messages before gameplay synchronization, acquire the gameplay lock nonblockingly for input, and repost contended input so presenter wake messages can run first.
- Keep game-domain events independent of the platform event representation. Use owned typed C++ payloads and cancellable completions for cross-thread work; the platform callback is only a coalesced, payload-free doorbell that asks the UI thread to drain the queue.
- When an owned string crosses back into a legacy script-name API, rematerialize it as a zero-initialized 32-byte field before lookup. Those APIs compare the entire fixed-width field; `std::string::c_str()` guarantees only one terminator and is not a zero-padded substitute.
- Dispatch synchronous host events directly when already on the UI thread. Cross-thread sends wait on a shared completion, and commands that historically used `ReplyMessage` acknowledge that completion before continuing long UI-thread work. Close the dispatcher only after producers stop, and release every queued waiter during cancellation.
- Keep cursor ownership split at the window boundary: the render child has no Win32 class cursor and SDL's cursor is hidden before wrapping it, while the framed parent retains its arrow for non-client UI. Game cursors are software-composited, including intentionally bitmap-less script cursors used during video playback.
- Keep indexed graphics as source/decode state and XRGB8888 as the only writable render/composition format. Expand an indexed source through its own palette at the draw boundary; never quantize it through a destination palette or a lower-precision packed format.
- Preserve legacy index-zero transparency in XRGB surfaces with a keyed-visibility marker in the ignored high byte. SDL presentation treats the surface as XRGB, while transparent scene composition tests the marker instead of RGB values.
- Keep standalone screenshots and savegame previews as separate serialization boundaries: standalone captures may preserve the XRGB framebuffer in a 32-bit BMP, while embedded save previews must remain the original indexed BMP format for cross-version save compatibility.
- Treat main-menu hover highlights as static BMP resources activated by script `PLAY` commands, not animation files. Ordinary shared resources may intentionally bind the same writable XRGB composition scene and expand directly into it.
- Do not use resource load order or an existing scene's pixel format to infer whether a resource is a source or a destination. Derive the role from script semantics: primary and ordinary shared resources are XRGB composition participants, while separated, control, load-only, permanent, and private helper resources remain indexed sources.
- A logical scene index is an ordering and script-binding key, not unique pixel-storage identity. Permit an XRGB composition scene and independent indexed source scenes at the same index; prefer the composition scene for index-based target lookup, and retain exact scene handles for source-specific operations.
- Font atlases use indexed pixels as masks, while script-supplied low/high colors select indices in the active game palette. Resolve the remapped glyph index through the active palette when writing XRGB; the font bitmap's own palette is not the text-color authority.
- Keep an XRGB-bound animation's indexed delta history local to the animation canvas. Decode with local origin and stride, retain only width times height indexed storage, and expand clipped dirty pixels into the shared XRGB destination at the resource offset; never allocate or materialize a zero-filled indexed shadow of the whole composition scene.
