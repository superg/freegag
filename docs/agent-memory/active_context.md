- Proposed authentic nostalgia mode (not yet implemented): represent the 640x480 logical display as one authoritative 8-bit indexed root plus a 256-entry active palette, select script resource variant 0, and let the existing indexed-to-indexed compositor remap each resource's private palette into that shared palette. Keep SDL, its texture, and the platform window XRGB8888; expand the indexed presentation front through the active palette immediately before snapshot/upload. Palette-only updates must invalidate/re-expand the whole visible front, and the presenter's root/front distinction must remain indexed (or otherwise retain equivalent index/blackout state) so reveal, blackout, fades, and palette cycling remain correct. The current per-scene indexed backing alone is insufficient because an identical index can denote different RGB colors in different resource palettes. A single startup-only `ColorMode=HighColor|Indexed256` setting would express the real user choice more accurately than independently selecting low-color resources; a boolean `IndexedColorMode` is the simpler schema alternative. This remains a design direction, not current project behavior.
- The old 256-color/high-color choice distinguished destination/display behavior, not CDF bitmap encoding. An exhaustive header audit found all 462 `.BMP` records in `Gag01.cdf` and all 628 in `Gag02.cdf` are uncompressed 8-bpp indexed BMPs with 40-byte `BITMAPINFOHEADER`s; all 94 `.256` records per archive use the same encoding. Their palettes use four-byte BMP `RGBQUAD` records in B, G, R, reserved order: color precision is 24 bits although each entry occupies 32 bits on disk, and the runtime deliberately ignores the fourth byte even where archive data leaves it nonzero. Ordinary assets contain 256 entries (1024 palette bytes) and start pixels at byte 1078; bitmap-class `FONT2.RUS` is the exception with 121 entries and a byte-538 pixel offset. Each archive contains that font record twice. With a 16-bit RGB565 destination, `build_indexed_to_16_palette` expands every source index through that resource's private palette, allowing the combined frame to contain colors from many independent 256-entry palettes. With an 8-bit destination, `build_indexed_to_indexed_palette` instead finds the nearest entry in the single active destination palette; `/F:NOPAL` resources deliberately avoid installing a competing palette in 8-bit mode, while the same guard permits their palettes when the destination exceeds 8 bits. Primary 8-bit resources install 236 palette entries. Thus there is no recovered 16-to-8 bitmap conversion: the low-color variants are authored/quantized alternatives intended to survive shared-palette display constraints, whereas the high-color variants remain compact indexed sources whose private colors are expanded at composition time.

Debug and Release builds plus `check-format` and `git diff --check` pass, and the user manually confirmed the affected save previews now render correctly.
- Project-owned native dialogs have been removed. Archive validation, window-class registration, and fatal runtime-exit errors now report the existing localized messages to `stderr` instead of calling `MessageBoxA`, and SDL's optional file-dialog subsystem is disabled. Debug and Release builds of the game, XTET library, and resource extractor pass after this cleanup; `check-format`, `git diff --check`, and a source scan for common-dialog/message-box remnants pass. SDL's statically linked Windows video backend still contains its own unused simple-message-box implementation and therefore imports `MessageBoxA`; SDL exposes no build option to remove that backend function independently.
- The first attempted fly-minigame pacing fix, deferring playback completion until estimated audible time, did not change the reported behavior and was fully removed. A closer legacy comparison found that animation audio's schedule marker originally appeared only after one fixed mixer block (about 186 ms for supported game PCM), whereas the per-voice SDL callback marked it on the first submitted bytes; the animation snapshot path could also retain a stale pre-reset marker and skip its wait entirely. Per-segment schedule progress now preserves the legacy block-boundary handshake and the local snapshot is cleared with the live markers. The user confirmed that this restores fly movement speed. Temporary instrumentation then established that clicking starts `FLMx-ul2.mov` directly with no script `WAIT`; its second frame waits 189 ms for audio schedule readiness before presentation. The longer legacy-feeling click-to-stab pause came from the shared mixer's phase: a newly queued sound could wait up to one partial global block before consuming its first full block, producing roughly 186–372 ms of transport latency, while a new per-voice SDL stream requests immediately and consistently lands near the minimum. All temporary logging source and its generated log were removed. No compensating gameplay delay or shared-phase emulation has been added.
