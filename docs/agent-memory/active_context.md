# Active context

- Startup is fully detached from the Windows registry. There are no production `Reg*` calls, registry API seams, installation/version checks, or logical-drive/CD discovery.
- The legacy archive/CD read-speed benchmark and startup speed gate have also been removed, including their API and tests.
- `ApplicationState::installation_path` is initialized to an empty prefix. `Gag01.cdf`, `XTETDLL.SFS`, autosaves, and generated `.GSF` paths resolve relative to the process working directory.
- Runtime settings and modern-window geometry persist in `freegag.ini` in the working directory. The file uses `[Game] Settings` and `[Window] Left/Top/Right/Bottom`; invalid or unavailable values fall back nonfatally.
- The optional `gag_resources.rc` build pipeline and `gag_resource_test` were removed. `src/resource_test.cpp` was deleted, and `advapi32` is no longer linked.
- Decompilation is considered complete; the project is now entering source cleanup and reorganization.
- First-party test sources, CTest targets, `GAG_TESTING` code, and explicit `*_for_testing` hooks remain intentionally absent. Tests may be reenabled later, but no restoration approach has been selected.
- Do not create, restore, or add tests unless the user explicitly instructs you to do so.
- Scripted in-game save/load is unconditional. `FREEGAG_IN_GAME_SAVE_LOAD` and the recovered native save/load dialog path have been removed. Screenshot export still uses its separate Win32 save-file dialog.
- Modern Windows compatibility is unconditional. `FREEGAG_WINDOWS_FIXES`, its legacy disabled branches, and the now-unreachable physical display-mode switching layer have been removed; fullscreen always uses the borderless-window path.
- Source-level decompilation metadata has been removed: executable-address annotations, structure size/offset assertions, provenance wording, empty application hooks, and an address-derived save function name. Script container parsing now initializes its carried truth value instead of emulating uninitialized stack data.
- Debug-only source paths are intentionally absent. All `_DEBUG` blocks, trace helpers/calls, trace counters, release-mode no-op macros, and debug-only ignored-result temporaries have been removed.
- C++23 is required globally from the root CMake configuration, with compiler-specific language extensions disabled; individual targets do not repeat the standard requirement.
- The root CMake formatting targets use root-relative recursive globs to discover all project-owned `.cpp` and `.h` files under `src/` and `tools/`; per-directory formatter lists are removed, and in-tree build/dependency sources are excluded by scope.
- XTET is integrated as a static library. Its application-facing integration is implemented in `src/xtet/integration.cpp`; unused DLL entry-point typedefs and an empty architecture guard have been removed. The script and startup contracts were not changed as part of this cleanup.
- XTET's direct Windows API calls are confined to `src/xtet/integration.cpp`: host window messaging, keyboard-message draining, and cursor coordinate conversion. Timing and animation delays use `std::chrono::steady_clock` and `std::this_thread::sleep_for`; the XTET target no longer links `winmm`. `src/xtet/api.h` retains Win32 handle and message types required by the game host interface.
- XTET initialization failures throw `std::runtime_error`. The existing startup exception boundary shuts XTET down and restores host state before rethrowing; XTET has no debugger-output or error-dialog path.
- The game uses the standard `main(int, char **)` entry point and is linked as a console application. `run_startup` obtains the process module handle internally, uses `SW_SHOWDEFAULT`, and detects `--xtet` directly from `argv`; internal Win32 runtime behavior remains unchanged.
- Project addons for scripted save/load and synthesized resources live under `src/extra/`: `save_load.*`, `synthesized_resource.*`, and `save_load_bg_patch.h`. They are listed directly by `src/CMakeLists.txt`; `src/extra` intentionally has no nested CMake file.
- The former startup monolith is split into stock-game modules directly under `src/`: `application`, `display_host`, `display_scene`, `runtime`, `script`, `runtime_tree`, `runtime_model`, `resource`, `media`, `text`, `audio`, and `game_host`. `startup.h` exposes only `run_startup`, and `startup.cpp` contains only startup orchestration and the Win32 message loop.
- Functional headers own subsystem declarations. Shared runtime layouts are preserved in ordered `*_types.h` headers, while mechanically shared legacy state and callback tables remain private to implementation files through `runtime_internal.h`; public consumers and addons do not include it.
- Architecturally, the game is a script-driven adventure runtime hosted by Win32. A dedicated script executor processes parsed runtime trees and coordinates the logical model, resources, scene compositor, media, text, audio, and the statically embedded XTET minigame; the main thread remains the Win32 UI/message thread.
- SDL 3.4.10 is fetched from its release archive with a pinned SHA-256 hash and linked statically only to the game. SDL shared libraries, test components, examples, documentation, and installation are disabled. The root project remains C++-only; SDL enables C within its own fetched project.
- Game audio uses one bound SDL3 audio stream per logical sound handle. Source WAV, animation, and XTET bytes remain in their original PCM format until SDL converts, resamples, and mixes them for a preferred float32 stereo 44.1-kHz playback device. The recovered integer converter, resampler, mixer, shared output blocks, and mixer-format switching are removed.
- Sound slots, queued segments, stream state, and fades are private to `audio.cpp`. Other subsystems use synchronized status snapshots and marker updates. Per-stream gain implements volume and a 5-ms `std::jthread` control loop drives float fades; the same worker advances source frames silently when SDL initialization, device opening, stream creation, or stream binding is unavailable.
- SDL audio-device opening occurs during sound initialization and reopening occurs during `resume_runtime_sound_output`. The temporary control-thread deferral and one-second retry machinery were an unsuccessful black-screen fix and have been removed after the actual content-validation fault was identified.
- The reported black screen was traced to a newly added generic animation-frame boundary validator rejecting the valid first frame of `LOGO1.mvz`. All content-validation rules introduced by the SDL audio refactor have been removed, and the temporary diagnostic logger, message scopes, counters, calls, and CMake entries have also been removed.
- Project code no longer contains WinMM audio/timer APIs or types and no longer explicitly links `winmm`; SDL may select WinMM-related Windows libraries transitively. WAV, animation, and XTET audio cross the game boundary through `RuntimePcmFormat`, with an explicit XTET adapter.
- All former `timeGetTime` and `GetTickCount` uses share `runtime_milliseconds()`, backed by `std::chrono::steady_clock` and returning the low 32 bits to preserve existing wraparound arithmetic.
- Runtime work is distributed across the UI thread, script executor, display-scene worker, SDL audio demand callback (or silent fallback worker), asynchronous file workers, and per-animation workers. Legacy non-audio subsystems continue to coordinate through shared state, mutexes/events/critical sections, queues, and Win32 window messages.
- Audio content retains the original engine's acceptance boundary. The refactored audio handle constructor keeps the legacy PCM/tag, mono/stereo, 8/16-bit, and minimum-rate checks, then derives block alignment and average byte rate as the old mixer did. Standalone WAV and animation audio traversal retain their pre-refactor assumptions; no new RIFF, frame-size, chunk-size, frame-alignment, or descriptor-consistency rejection is applied.
- A repository-data audit found CDF WAV inputs in PCM mono 8-bit 22.05 kHz, mono 16-bit 11.025 kHz, and stereo 16-bit 11.025 kHz formats; these descriptors and bytes now enter their SDL voice streams unchanged.
- Verified Debug and Release MSVC builds of the game, XTET static library, and resource extractor after restoring the legacy audio-content acceptance behavior. The repository `check-format` target and `git diff --check` pass. User verification of the reported black-screen/startup hang fix and broader manual audio coverage remain outstanding.
- The user has manually confirmed that audio appears to work correctly after the SDL stream conversion and cleanup. Detailed A/B assessment of perceptual differences from the legacy integer mixer has not been performed.
- SDL_mixer integration is intentionally deferred. Base SDL3 already owns conversion, resampling, float mixing, and device output; the remaining project audio code preserves game-specific handles, queues, looping, markers, silent progression, and animation synchronization.
- Final framebuffer presentation now uses SDL3. SDL wraps the existing Win32 capture child, owns an automatically selected non-VSync renderer and a nearest-filtered streaming XRGB8888 texture, while Win32 continues to own window creation, input, cursor behavior, dialogs, and message dispatch.
- The graphics pipeline now uses XRGB8888 for every writable composition and presentation destination: offscreen writable scenes, the compositor root, the visible front buffer, queued snapshots, standalone text and previews, and the XTET framebuffer. SDL receives the 32-bit rows directly without RGB565 expansion.
- Static bitmap/font resources and non-primary animation scenes remain indexed source surfaces. Indexed pixels are expanded through their own palette only while drawing into XRGB8888; the legacy destination-palette nearest-color remap and RGB565 packing paths are no longer active. Primary animations retain a private indexed history plane only when delta decoding into a writable XRGB destination requires it.
- Internal XRGB pixels use the ignored high byte as a keyed-visibility marker rather than alpha. This preserves index-zero transparency through XRGB-to-XRGB composition without reducing RGB precision.
- Standalone user screenshots are written as 32-bit BMPs. Savegame-embedded previews deliberately retain the original 8-bit indexed BMP structure and palette quantization so old and new saves remain format-compatible.
- Cross-thread presentation uses three reusable full-frame snapshots and a private child-window message. SDL renderer calls stay on the UI thread, transition snapshots retain order, and presenter shutdown cancels blocked producers before the display worker is joined.
- DirectDraw, native display-mode enumeration/validation, GDI DIB framebuffer presentation, and unreachable GDI media presentation hooks and context fields have been removed. `gdi32` remains linked for unrelated Win32 window-class background handling.
- Fresh x64 MSVC Debug and Release configurations build the game, XTET static library, and resource extractor with the lazy XRGB graphics pipeline. `check-format` and `git diff --check` pass; manual intro, main-menu static hover substitutions, animation palette/delta outside the main menu, transition, text, save-preview round-trip, standalone screenshot, scaling, fullscreen, repaint, XTET, and forced-failure coverage remains pending.
- Resource construction now assigns an explicit scene role from script semantics rather than from load order. Primary and ordinary shared resources bind writable XRGB8888 composition scenes; separated, control, load-only, permanent, and private helper resources retain indexed source scenes. The logical scene index controls ordering and script lookup but is no longer treated as unique pixel-storage identity: one XRGB composition scene and independent indexed sources may coexist at the same index, and index lookup prefers the composition scene while each source retains its exact scene handle.
- Main-menu hover highlights are static BMP resources activated with script `PLAY` commands. They bind the same XRGB composition scene as the menu background and expand directly into it. In the credits tree, the permanent 2x2 `Credits.mov` indexed source can now coexist at scene index 0 with the 640x480 `crd1.bmp` XRGB background instead of blocking its construction. This addresses the missing hover and missing credits-background failures without a new static data store or persistent 32-bit asset cache.
- Debug and Release builds of the game, XTET static library, and resource extractor pass after the explicit scene-role/binding fix. `check-format` and `git diff --check` pass. Manual verification of menu hover substitutions, the credits background and scrolling text, and surrounding transitions remains pending.
- The first XTET runtime check exposed a cross-thread lock cycle: its worker could hold the gameplay mutex while waiting for space in the bounded presentation queue, while the UI thread blocked on that mutex before it could service presenter messages. XTET window dispatch now ignores unrelated messages and uses a nonblocking gameplay lock for keyboard and mouse input; contended input is reposted behind already queued presenter work. Debug and Release game builds plus both XTET/resource-extractor configurations pass; user confirmation of the minigame fix remains pending.
- The render child has no Win32 class cursor, and SDL's cursor is hidden before SDL wraps that child. This prevents SDL's outer window procedure from briefly installing its default arrow before the game procedure clears it when mouse movement occurs over video scenes whose scripts intentionally select the bitmap-less `MM` cursor. `GR.CIN`'s chicken look-up and `GRTV.CIN`'s TV movie sections both intentionally bind `MM`; the framed parent retains its normal system cursor for borders and menus. Debug and Release game/XTET/extractor builds, `check-format`, and `git diff --check` pass; manual confirmation of both reported playback cases remains pending.
- Script text colors are palette indices produced by remapping the indexed font-atlas masks. XRGB text drawing now resolves those indices through the active game/display palette, matching the original indexed destination semantics; resolving them through the font bitmap's private palette caused dark subtitles.
- XRGB-bound animations retain an animation-sized private indexed history canvas with local coordinates and stride. Delta decoding and palette changes operate on that canvas, and only its clipped dirty region is expanded at the animation's destination offset. The former full-scene zero-filled history could overwrite unrelated portions of a shared composition scene with black when an animation palette chunk was processed.

- The first attempted fly-minigame pacing fix, deferring playback completion until estimated audible time, did not change the reported behavior and was fully removed. A closer legacy comparison found that animation audio's schedule marker originally appeared only after one fixed mixer block (about 186 ms for supported game PCM), whereas the per-voice SDL callback marked it on the first submitted bytes; the animation snapshot path could also retain a stale pre-reset marker and skip its wait entirely. Per-segment schedule progress now preserves the legacy block-boundary handshake and the local snapshot is cleared with the live markers. The user confirmed that this restores fly movement speed. Temporary instrumentation then established that clicking starts `FLMx-ul2.mov` directly with no script `WAIT`; its second frame waits 189 ms for audio schedule readiness before presentation. The longer legacy-feeling click-to-stab pause came from the shared mixer's phase: a newly queued sound could wait up to one partial global block before consuming its first full block, producing roughly 186–372 ms of transport latency, while a new per-voice SDL stream requests immediately and consistently lands near the minimum. All temporary logging source and its generated log were removed. No compensating gameplay delay or shared-phase emulation has been added.
